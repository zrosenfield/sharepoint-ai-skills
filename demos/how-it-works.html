The architecture
Three layers — only one changes per report
1
Style
CSS custom properties define every visual decision — color, type, spacing, radius. The same four palette classes (palette-warm-paper, palette-deep-ink, palette-clean-white, palette-slate) apply to all four skills identically.
Deterministic — same class, same output, always.
2
Components
Each skill has a catalog of named blocks — hero sentence, KPI row, trend chart, bar list, compare strip, highlights. The AI reads the data and decides which blocks to use and in what order. A sales report gets a trend. A headcount report gets a status grid.
AI-assembled — the skill picks the right blocks for the story.
3
Data
Before rendering, the skill builds a validated JSON document — the "consistency layer." Every block, every value, every label is in the JSON. The HTML is 100% determined by the JSON. You can regenerate the same report from the JSON at any time.
Same JSON → same HTML. Every time. No drift.

How you could build the next one
The HTML-first workflow

Start with a beautiful HTML

You don't write a design spec. You make (or find) the HTML you want the output to look like — a mockup, a reference, a template you already have.

Then you hand it to the AI: "Turn this into a reusable skill."

The AI reads the HTML, extracts the visual language, and writes the template file and SKILL.md automatically. The design becomes the spec.

What the AI extracts

  • 1
    Palette tokens — color variables pulled from the CSS, named and documented
  • 2
    Component patterns — recurring structures (KPI card, bar row, callout) identified and catalogued
  • 3
    Template slots — placeholder tokens added where data goes ({{BLOCKS}}, {{HERO}})
  • 4
    Interview questions — written into SKILL.md so the skill knows what to ask the user
  • 5
    JSON schema — the data shape that drives the render, documented and validated

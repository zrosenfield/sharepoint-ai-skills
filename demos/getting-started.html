HTML Generation · Three Approaches

Three ways AI generates HTML reports.

The same prompt, the same output quality — but very different architectures underneath. Each approach makes different trade-offs between simplicity, reusability, and flexibility.

The approaches
From simplest to most powerful
1

Hardcoded output

The AI writes everything — content and markup — in one shot. Every update means regenerating the whole file.

Simple to prompt — just describe what you want
All content lives in the HTML; no separate data file
Style varies each generation — not guaranteed consistent
To update the data, regenerate the whole report
Best for:  one-off reports, quick wins, exploratory outputs
Prompt + data
"Build a hiring report.
47 candidates, 8 roles..."
↓ AI writes everything
Complete HTML
<h1>Hiring Report</h1>
<div>47 candidates</div>
<div>8 open roles</div>
<style>...all CSS...</style>
Every value, every color, every layout decision baked in.
2

JSON blob + template

The template defines structure and style (fixed). The JSON blob carries the data (variable). Only the blob changes each run.

Style is guaranteed — the CSS never changes
Updates are cheap — swap the JSON, re-render
The JSON is the consistency layer — same input, same output
Structure is fixed — every report has the same layout
Best for:  recurring reports with a fixed structure (quarterly, weekly)
Template (fixed)
{{REVENUE}}
{{DEALS}}
{{REGION_BARS}}
JSON blob (changes)
"revenue": "$4.2M"
"deals": 47
"regions": [...]
↓ AI fills the slots
Rendered HTML
$4.2M ← revenue slot filled
47 ← deals slot filled
████░░ ← bars filled
Like a mail merge. The form never changes; only the data does.
3

Component library

A shared palette and a catalog of named blocks. The AI picks which components to use and in what order — based on what the data's story calls for.

Style is shared across every report in the family
Structure varies — the AI assembles the right blocks for the story
Revenue report and people report look related but aren't the same layout
Adding a new report type means choosing from existing components, not redesigning
Best for:  a family of reports that need to feel like one system
Component catalog (shared)
hero kpi-row trend bar-list compare table status-grid highlights
↓ AI selects + sequences
Revenue
hero kpi-row trend bar-list compare highlights
People
hero status-grid compare table bar-list highlights
Same CSS. Different structure. Both unmistakably the same design system.
Trade-offs
Choosing the right approach
1 · Hardcoded 2 · JSON + Template 3 · Component library
Setup effort None — just prompt Build the template once Build template + component catalog once
Style consistency Varies each run ✓ Guaranteed by template ✓ Guaranteed by shared CSS tokens
Layout flexibility Each generation can differ Fixed — same layout every time ✓ AI assembles the right structure for the data
Cross-report family ✗ Not applicable Only within one template ✓ All reports in the family share one design system
Incremental update Full regeneration ✓ Swap JSON, re-render ✓ Swap JSON, re-render

Getting started
Run your first demo in under 5 minutes

Setup steps

  • 1
    Install the skill Upload the skill folder to AgentAssets → Skills in your SharePoint site. The agent discovers it automatically.
  • 2
    Prepare your data Either import the demo CSV into a SharePoint list, or attach the CSV file directly in the chat before sending the prompt.
  • 3
    Send the prompt Copy a prompt from the five below. The skill interviews you if anything is missing, then builds the JSON and renders the HTML.
  • 4
    Open the file The skill delivers a self-contained HTML file. Open it in any browser — no server, no CDN, no dependencies.
